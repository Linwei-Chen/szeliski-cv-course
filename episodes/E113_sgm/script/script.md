# E113 口播稿 · 半全局匹配 SGM：多方向一维优化

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

这一集讲 SGM，半全局匹配。书上第 774 页说：动态规划立体匹配，是在两条对应扫描线的所有两两匹配代价矩阵里，找一条最小代价路径。上一集的块匹配只看局部窗口；SGM 把一整行连起来看，让视差沿扫描线平滑变化。它先算代价体，再在代价体上找路径。路径经过的每个点就是一个视差值，整条路径的代价最小，等价于在扫描线上做一次全局选择。DP 假设扫描线内顺序不变，这是一个很强的假设。代价体的每一层对应一个视差，路径在层与层之间走，就把整行的视差串了起来。

书上第 774 页说：部分遮挡可以显式处理，把一张图里的一组像素分配给另一张图里的一个像素。书上第 775 页说：动态规划的每个状态，把 DSI 匹配代价和前驱代价相加，还要给遮挡像素加一个固定惩罚。路径每一步可以向右、向下或斜着走。斜着走表示匹配，水平或垂直走表示遮挡。遮挡惩罚让算法在匹配错和承认看不见之间做选择；顺序约束要求左右图的像素顺序不能乱。惩罚让路径不轻易跳过。遮挡惩罚通常小于匹配错代价，太大就会把匹配也当成遮挡。斜走一步表示左图一个像素匹配右图一个像素，水平或垂直走表示一个像素被遮挡，路径不轻易跳过任何一边。

书上第 775 页说：动态规划有两个问题，遮挡像素的代价不好选，扫描线之间的一致性难保证；它还需要顺序约束。一行一行独立优化，行与行之间可能不一致，结果会出现横向条纹。顺序约束在窄前景物体上会被违反，因为前景会把后面的点挡住。所以一维 DP 快，但不够稳，需要多方向。条纹是行与行之间不连续；顺序约束是物理上左右图对应点的顺序应当一致，窄前景会破坏它。一维 DP 的全局最优只在单行成立，不是整图最优。

书上第 775 页说：把多个方向的累积代价加起来，可以得到质量高得多的结果；比如八个方向，N、E、W、S、NE、SE、SW、NW。这样得到的半全局匹配 SGM 效果很好，而且非常高效，能做实时低功耗实现。SGM 的做法，是多找几个方向，各自做一维 DP，再把代价加起来。它没有解二维全局优化，用多个一维方向做近似，既保留边界，又比全局优化便宜。八个方向不是必须，四个方向已经能压住大部分条纹；方向越多越贵。SGM 的名字是半全局，它没有解二维 MRF。方向越多，累积的代价越稳，计算和内存也跟着涨。四个方向是常用的工程折中。

看图：左到右、右到左、上到下、下到上，四个方向各自做一维动态规划，然后把四张累积代价图相加。方向越多，越不容易出现单方向条纹，但计算和内存也越大；工业上常用四个方向或八个方向。每个方向只沿一条线传播，所以 SGM 是半全局：比局部方法看得远，比全局方法少算很多。每个方向只传播一行或一列的代价；四张图相加后，每个像素的代价融合了四个方向的支持。四个方向已经能明显减轻条纹；八个方向更稳，但更慢。

书上第 775 页说：遮挡像素有固定惩罚；SGM 把这个惩罚扩展成 P1 和 P2 两项。P1 是相邻像素视差变 1 的代价，P2 是视差大跳变的代价，一般 P2 大于 P1。P1 允许斜面和缓慢变化，P2 阻止跨越深度边界。P2 太小，边界会糊；P2 太大，弱纹理会被人为拉平。很多实现让 P2 随图像梯度自适应：边缘处减小 P2，保住边界。我们的实验取 P1 等于零点零二、P2 等于零点一二。P1 小，允许斜面；P2 大，阻止跨越深度边缘。P2 的取值要在边界和弱纹理之间权衡，换场景往往要重新调。P1 和 P2 一起决定路径愿不愿意跨过深度跳变。

看图：左边是总体、弱纹理、边界三组误差，灰色是块匹配，红色是 SGM。总体误差从零点九八降到零点四四像素；弱纹理从十点三一降到三点三三；边界从四点五九降到一点四一。块匹配在弱纹理块里几乎在瞎猜，因为局部窗口没有图案；SGM 靠周围的平滑传播，把视差填得更接近真值。边界上 SGM 也更稳，因为它不只看一个小窗口。弱纹理块里，局部窗口没有图案，块匹配的代价曲线很平；SGM 的平滑项把周围视差传了进来。我们的弱纹理块是人为挖出来的，真实场景的弱纹理更隐蔽。

实验设置：把上一集的合成双目降到 320×240，视差范围 0 到 85，用 3×3 SAD 代价；在背景左上角挖一块没有纹理的平地，左右图都填成同一个灰度。这块平地就是弱纹理陷阱：局部窗口里所有视差都差不多，块匹配会乱选；SGM 能把周围的视差传播进来。所有统计都剔除遮挡和边界，弱纹理块单独统计。下采样到 320×240，是为了让四路径 DP 在可接受时间内跑完；视差范围也减半到 0 到 85。统计剔除遮挡和边界，是为了看算法在可匹配区域的能力。

实验结果是：SGM 总体零点四四像素，块匹配零点九八；弱纹理三点三三对十点三一；边界一点四一对四点五九；平滑度 SGM 也更低。SGM 没有把所有错误都消掉，它只是把弱纹理和边界的错误压了下去；遮挡区它仍然没有办法，因为那里真的没有对应像素。SGM 的输出还要做左右一致性检查、亚像素和补洞，才能变成可用的深度图。SGM 的收益主要来自弱纹理和边界；总体误差降低一半，但遮挡区仍然错。SGM 在边界上更好，是因为多方向累积抑制了单行错误。在可匹配区域，SGM 的视差明显更接近真值。遮挡区和边界之外，剩下的错误还要靠后处理收尾。

看图：真值、块匹配、SGM 三张视差图。块匹配在弱纹理块里是一团噪声，SGM 基本填成了背景视差；边界上 SGM 也更整齐。SGM 也有它的问题：细长结构、重复纹理、强遮挡边缘仍会错；P1/P2 调不好，边界会糊，或者弱纹理被拉平。SGM 是工程折中，谈不上完美。SGM 的视差图更平滑，但细结构会被平滑掉，这是 P2 的取舍。细长物体也会被平滑掉，这是半全局方法的通病。

工程边界方面，SGM 要存整个代价体，内存是宽乘高乘视差范围；视差范围大、分辨率高，内存和带宽就吃紧。P1/P2 没有通用值，要按场景和噪声调；实时实现常用多核、SIMD 或 FPGA。SGM 对弱纹理和边界有效，但对遮挡、细结构、重复纹理仍会错；它也不理解语义。下游要配合置信度、左右一致性、时域滤波，才能稳定。内存和带宽是 SGM 的硬约束；实时实现常用行缓冲、多核和定点化。参数没有通用值，换场景要重新调；这也是深度学习方法出现的一个动机。这也是后来深度学习方法进入立体匹配的一个动机。把规则写死，换场景就要重新调参。

这一集收成三句话。第一，SGM 用多个方向的一维动态规划近似二维全局优化，是速度、内存、效果的折中。第二，P1/P2 控制平滑和边界，参数要按场景调。第三，SGM 能改善弱纹理和边界，遮挡和细结构仍要靠后处理。下一集讲端到端立体匹配：PSM-Net 怎么用 3D 卷积在代价体上学习，代价体怎么神经化。这一集讲手工规则，下一集讲从数据里学规则。记住三个词：多方向、P1/P2、半全局。下一集见。
