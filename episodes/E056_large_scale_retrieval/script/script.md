# E056 口播稿 · 海量特征怎么检索：视觉词袋、词汇树与实例检索演进

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

上一集我们把认出这一个的两步学会了，先提特征找匹配，再用几何验证筛掉假配对。可马上有个现实问题，数据库里不止一张图，是几十亿张视频帧。一张一张比过去，等结果出来就太晚了。书上第 448 页把这个坎说得很直白，数据库一大，逐张匹配的时间代价高得没法接受。今天这集讲检索，海量图库里，怎么又快又准地锁定候选。检索要解决的就是这个查找速度。

书上第 448 页给的思路是两段式。先快速粗筛，把几十亿缩小到少数几个可疑对象。再用更保守的验证，一个一个精比。粗筛求快，验证求准，分工明确。这跟翻书找内容一样，先查目录锁定页码，再逐行细读。这一集后面所有办法，都在回答同一个问题，粗筛那一步，怎么做到又快又不漏。候选越少，后面的精比就越省。

粗筛的办法不是视觉界先想出来的。书上第 448 页说，快速找出文档之间的部分匹配，本来就是信息检索这个领域的核心问题。经典做法是倒排索引，预先把每个词出现在哪些文档里记下来，查询的时候按词直接定位文档。书上第 449 页还补了一句，词在文档里出现的频率，正好拿来快速找出和查询匹配的文档。搜索引擎的关键词搜索，底层就是这套记录，几十亿网页凭什么零点几秒出结果，靠的是提前建好的索引，现查现算谁都等不起。索引只是把查找提前做好，查询时不必从头扫一遍。

视觉界对应的问题叫什么？书上第 448 页给了两个名字。在大图集里找某个特定物体，叫内容检索。认出这一个的检索任务，叫实例检索。上一集结尾引的那句原书自注，指向的就是这一节。那文档有词，图里靠什么？书上第 449 页接话，把图里的高维特征描述子，先映射成离散的视觉词。图一变成一袋词，文档检索那一套就能照搬过来。词袋就是把一张图表示成一群视觉词。

第一个把这件事做成系统的是 Video Google。书上第 449 页说，Sivic 和 Zisserman 率先把信息检索技术搬到视觉搜索。给要索引的每一帧视频检测仿射不变特征，一种围着 Harris 角点做形状自适应区域，另一种叫最大稳定极值区域。再对每个归一化区域算 128 维的 SIFT 描述子。检测出的大量特征，就是接下来要变成词的原材料。Harris 角点找的是轮廓拐弯的地方，最大稳定极值区域找的是一块块稳定的区域，两个各有所长，书里让它们搭档上场。

这里有个不起眼但关键的预处理。书上第 449 页说，用帧间跟踪到的特征累计统计，估出描述子的平均协方差矩阵，按它定义马氏距离。第 5 章提过这个距离。实践中把描述子预先乘上协方差矩阵平方根的逆，各方向拉伸到同一尺度，之后用普通欧氏距离就够。书里的脚注还特别交代，这么做，比直接在描述子空间做主成分分析更讲道理。

接下来是正题，特征怎么变成词。书上第 449 页说，Sivic 和 Zisserman 最早用 K 均值聚类做映射，后来的方法换上了词汇树、随机森林这类替代技术。这跟编词典一个道理，千千万万个外观相近的特征归到同一个词底下，图就成了一袋词。词汇树内部具体怎么组织，书里把细节放在了第一版书的 14.3.2 节，本节只给结论。映射得越准，词袋越能代表这张图。

聚类要算多久？书上第 449 页说，只用几百帧视频来学聚类中心，也要从大约三十万个描述子里估出几千个词，后来的工作把这个容量又扩大了很多。查询时，新区域里的每个特征都映射到对应的视觉词。还有一道防污染工序，最常用的那些视觉词单独拉成停用表，直接丢弃，免得处处出现的模式把结果带偏。这跟文章里的的、了、是一个道理，家家都有，说明不了这篇文章是谁写的。

这套办法到底有多快？书上第 449 页到第 450 页说，Nistér 和 Stewénius 的词汇树识别系统，靠着量化与打分两边都高效，对四万张 CD 封面的数据库做到实时应答。数据库换成一百万帧电影画面，也能每秒查一轮。那个年头，一张 CD 封面就是一个待认的物体，四万张实时认，商店盘点这类活立刻能想见用途。2006 年的硬件，一秒过一百万帧，粗筛这一步，从此不再是瓶颈。实时意味着查询一到，结果马上能给出。

进入两千年代，实例识别系统快速进化。书上第 450 页说，Philbin 等人的对比实验发现，随机森林加 K 维树，在大型位置识别任务上表现比词汇树好。他们还比较了验证阶段用不同二维运动模型的效果。检索粗筛完，几何验证那一关跑不掉，正是上一集讲的四步法。位置识别就是我现在在哪，手机扫街景认地标，用的正是这条路。认的是整张图的方位，不是单个物体，任务变了，检索的索引结构也得跟着换。

文档界还有一个办法被搬了过来。书上第 450 页说，Chum 等人在后续工作里用了查询扩展，把初查排名靠前的图，再当成新的查询提交一遍，滚雪球式地召回更多候选。书里脚注补了一句，它的替代方案叫数据库侧扩充。像顺藤摸瓜，找到一根好藤，就顺着它再摸一把。

词袋有个老毛病，一个特征硬塞进一个词，落在边界上的就容易分错。书上第 450 页说，Philbin 等人用软分配来缓解量化问题，每个描述子映射到若干个邻近视觉词，跟更早提出的多重分配思路类似。代价书里也挑明，词向量的稀疏性下降，内存和计算开销都变大。以前一个特征只投一个词的票，现在改成投好几票，边界上的特征不容易站错队，代价是票箱变多，数票更贵。

同一年还有人在粗排里加入几何信息。书上第 450 页说，Jégou 等人在大规模排序阶段就纳入部分几何信息，并给局部描述子显式建匹配方案。这些算法凑到一起，把实例识别推到了网络规模，检索、匹配、三维重建，三个任务一起上。网上几十亿张照片能拼出整座城市的立体模型，靠的就是这套检索打底，第 11 章会正面讲三维重建。

2012 年深度学习革命之后，方向又变了。书上第 450 页说，研究者开始开发神经特征检测器和描述子，有时干脆组合成端到端匹配系统。书里脚注里有个细节，流行的开源大规模重建系统 COLMAP，到今天还在用传统特征和索引方案，老方法一直有生命力。

书上第 450 页到第 452 页配了两张图。一张画实例检索的里程碑，标出从手工特征到卷积网络方法的迁移。一张画典型流水线，特征提取、编码、索引三段，深度学习框架里常常坍缩成一段。这两张图把二十年收拢成一眼。想深挖，书里还指了三个方向，全局描述子的视觉相似搜索、位置识别、社区照片的大规模三维重建，都给了交叉引用。这一页的示意图是程序生成，没有用原书原图。

收个尾。这一集讲了二十年检索演进。文档界的老办法，倒排索引、词频、停用词、查询扩展，配上视觉里的新词，视觉词袋、词汇树，撑起了海量实例检索。不变的是先粗筛后精验的两段式，变的是特征从手工走向神经。这套倒排索引加视觉词袋的组合，第 7 章正课到特征匹配那一站还会回来细讲。下一集我们回到第 6 章主线，书上第 349 页，图像分类，认出这一类，下集见。
