# E069 口播稿 · 匹配的保险丝：比率测试、互检与几何校验联防

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

提完特征和描述子之后，下一步是在两幅或多幅图像之间建立初步匹配。书上第 441 页说，采用什么策略，部分取决于应用：已知重叠的图像，比如拼接，和可能完全不对应的图像，比如数据库检索，策略不同。重叠图像里，多数特征可能匹配上，但有些会被遮挡，或者外观变化太大。匹配没有一套固定流程，先问这两张图大概有没有关系。

这一节把匹配拆成两个组件。书上第 441 页说，先选匹配策略，决定哪些对应进入下一阶段；再设计高效的数据结构与算法，把匹配做快。一个管留哪些，一个管怎么找得快。这一集先讲前者，后面再讲索引结构。策略错了，后面再快也没有用。

先假设描述子设计得让特征空间里的欧氏距离可以直接给候选匹配排序。书上第 441 页说，如果某些轴更可靠，最好先按已知好匹配的变化幅度重新标定这些轴。更一般的做法，是把特征向量变换到新的缩放基，这叫白化。先把每个分量的话语权调平，再量距离，免得某个噪声大的分量带偏。这一步不做，距离就会被大方差的分量绑架。

最简单的策略是设一个最大距离阈值，把阈值内的匹配都返回。书上第 441 页说，阈值太高，假阳增多，也就是错配被返回；阈值太低，假阴增多，也就是正确匹配被漏掉。图 7.21 用固定圆和虚线圆画出了这两种情况。阈值像筛子，孔太大漏进沙子，孔太小把米也挡了。所以单靠一个阈值，很难同时兼顾不漏和不错。

书上第 442 页的表 7.1 给出一个混淆矩阵的例子：十八个真阳、四个假阳、两个假阴、七十六个真阴。真阳是正确匹配，假阴是没检出的正确匹配，假阳是提出的错误匹配，真阴是正确拒绝的非匹配。四个格子把答对答错、该配不该配，分得清清楚楚。这四个数也是后面算率和画 ROC 的原料。

把这些数变成比率，就有真阳率、假阳率、阳性预测值和准确率。书上第 443 页说，检索文献里，阳性预测值叫精确率，真阳率叫召回率。精确率和召回率可以合成 F 值，F 值是它们的调和平均。一个问报出来的有多少是真的，一个问真的有多少被报出来。F 值高，说明两边都不太差；一边偏科，它就会掉下来。

理想情况是真阳率接近一、假阳率接近零。书上第 443 页说，改变阈值会得到一族点，连起来就是 ROC 曲线。曲线越靠左上、曲线下面积 AUC 越大，性能越好。书上第 444 页说，也可以用等错误率；图 7.22 还画了匹配与非匹配数量随特征距离变化的分布。ROC 把筛得全和筛得准的取舍画成一条线，AUC 给一个总分。AUC 反映所有可能阈值下的总体排序能力，不绑定单一阈值。

固定阈值的问题是难设。书上第 443 页说，有用的阈值范围会随特征空间的不同区域变化很大。更好的策略是直接找特征空间里的最近邻。但有些特征本来就没有匹配，比如背景杂物或者被遮挡，所以仍要留一个阈值压假阳。书上第 443 到 444 页说，理想情况下阈值能随区域自适应，有足够训练数据时甚至可以学出来。与其全图一个死阈值，不如先找最近的那个，再看它像不像。

在拼接或无序照片建三维模型时，常用一个启发式：比较最近邻距离和次近邻距离。书上第 444 页说，次近邻最好取自一张已知不匹配的图像，比如数据库里的另一个物体。最近邻距离比次近邻距离，就叫 NNDR；DA 是目标描述子，DB 和 DC 是最近的两个邻居。看的不是最近的多近，而是最近比第二近领先多少。如果第一名只比第二名近一点点，这个匹配就很可疑。

书上第 445 页的图 7.23 说明：固定阈值下，DA 配不上 DB，DD 却错配 DC 和 DE。只取最近邻，DA 能配对 DB，但 DD 仍会错配 DC。用 NNDR，小的 d1 比 d2 正确接受 DA 配 DB，大的 d1 撇比 d2 撇正确拒绝 DD。比率小，说明第一名遥遥领先；比率大，说明第一名和第二名差不多，不可信。图里那条虚线圆，就是固定阈值兜不住的反例。

书上第 444 页说，近期工作表明，相互 NNDR，或者至少带交叉一致性检查的 NNDR，明显优于单向 NNDR。不光 A 认 B，还要 B 也认 A；两边都点头，才算数。互检尤其能挡住一对多的错配。

选定策略后，还要高效搜索候选。书上第 445 页说，最简单是全对全比较，传统上太贵，但现代 GPU 已经能承受。更高效的是建索引结构，比如多维搜索树或哈希表，可以按图建，也可以给整个数据库建。超大数据库还会用词汇树、乘积量化或倒排多索引。先在索引里圈出可能的一小撮，再仔细比，不必人人都比一遍。索引只负责变快，不负责变准；准不准还要靠前面的策略。

书上第 445 到 446 页说，多维哈希把描述子映射到固定大小的桶；查询时把新特征哈希进桶，再搜邻近桶。MOPS 的例子把八乘八图块的四个象限求和，得到三元素索引，再映射到十个一维桶里最近的两个，三维索引共八个桶。书上第 446 页说，更通用的是局部敏感哈希，用多个独立哈希函数取并集；也有把高维描述子变成二值码、用汉明距离比较的做法。哈希像先按大致方位分抽屉，只在相关抽屉里翻。桶分得越粗，找得越快，但漏掉真邻居的风险也越大。

书上第 446 页说，另一类常用结构是多维搜索树，最有名的是 k-d 树，沿交替的轴对齐超平面切分特征空间。切分尽量让树平衡；查询时先定位到所在箱，再搜邻近叶，直到能保证找到最近邻。书上第 446 到 447 页说，最佳箱优先搜索按空间邻近顺序搜箱，通常更高效。像查邮编，先翻对区，再翻邻区，不必从第一页翻起。树建得好不好，直接决定查询要翻多少叶。

书上第 447 页说，Muja 与 Lowe 比较了多种方法，结论是多个随机化 k-d 树往往性能最好。现代近似最近邻库有 FLANN 和 Faiss。工程上不必自己造轮子，先看成熟库的默认配置。库的默认参数通常够用，但数据规模变了要重新调。

书上第 447 页说，拿到候选匹配后，可以用几何对齐验证哪些是内点、哪些是离群点。书上第 447 到 448 页说，先抽一小批种子匹配拟合全局变换，再验证更多匹配，这个过程常叫随机采样或 RANSAC。书上第 448 页说，初始对应建立后，有些系统还会沿极线或全局变换邻域补匹配；也可以用神经网络做匹配过滤，比如 SuperGlue。外观说像，几何还要说摆得进同一个变换；两道都过，才算可靠。RANSAC 也有失效的时候：内点太少，会拟合出错误的变换。下一集换一条线，讲边缘和轮廓，从点匹配走到线和边的检测。
