# E137 口播稿 · 数据集、开源工具与你下一步的路线

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

这是正课第一百二十九集，也是整门课的最后一集。前面一百二十八集都在讲算法，这一集讲学完之后去哪找东西。书上第 954 页说，附录 C 汇总对学生、教师、研究者有用的补充材料；书网站还有更新的相关课程列表。这一集不教新公式，只给三样东西：数据集、工具、下一步路线。信息密度高，建议暂停记笔记；先看目录，再决定跳哪一段。这也是全课唯一一集不讲算法的正课，把它当索引，不必一次记住。

怎么选数据集？书上第 954 页说，可靠算法的关键之一，是在有挑战、有代表性的数据集上测试；有真值或别人的结果时，测试更有信息量、更定量。自己造几张图跑通，只能说明代码能跑；放到公开数据上，才知道它是不是真的能用。选数据集看三件事：任务像不像、标注够不够、有没有排行榜；任务像，才有意义；标注够，才能算分；有榜单，才知道自己排在什么位置。公开数据集还有许可证和隐私问题，商用前看清条款；许可证分学术/商用，隐私要看人脸/车牌/医疗数据，别拿敏感数据练手。

书上第 954 页说，多年积累的数据集很多，比如 Middlebury 立体、PASCAL、ImageNet、KITTI、Sintel、COCO；很多数据集还带排行榜，能查到最新结果和代码；旧数据集可以在第 1 版附录 C.1 和 VisionBib 找。识别看 ImageNet/COCO，光流看 Middlebury/Sintel/KITTI，立体看 Middlebury/ETH3D，三维看 ScanNet/DiLiGenT。先按任务找数据集，再看榜单和代码；不要拿一个数据集打天下；同一任务可能有多个数据集，先选有榜单、维护活跃的；附录 C.1 按章节列了数据集，本身就是索引；ADE20K/Cityscapes 做分割，ScanNet 做室内三维，KITTI 做自动驾驶。

书上第 960 页说，很多算法在 KITTI 上训练又在 KITTI 上测试，换一个数据集就掉点。这就像只在自家门口练车，换一条路就不会开；模型可能只是没见过别的场景。看论文时先看训练集和测试集是不是同一个；如果是，分数要打折；更要看跨数据集、跨场景的表现；掉点不一定是坏事，它告诉你模型的边界在哪。跨数据集是论文审稿最常问的问题之一；domain adaptation 是正经研究方向，先做基线，再谈泛化。

看速度实验。同一组 128 到 1024 的合成图、同一个 9×9 高斯核，三种实现差多少？1024×1024 时，OpenCV 约 0.006 秒，SciPy 约 0.042 秒，NumPy 约 0.61 秒；相对 NumPy，OpenCV 快约 105 倍，SciPy 快约 15 倍。这不是说 NumPy 没用——写原型它最直观；但产品里要把热点换成优化库。边界说清：单机、单操作、合成图，绝对时间会随硬件和版本变；不是通用 benchmark；NumPy 的慢主要在 Python 层循环，向量化后差距会缩小；计时只测模糊，不含读写图和色彩转换；三次取中位数，减少抖动；图里只看趋势：像素越多，三种实现都变慢，差距是常数级，不是算法级。

书上第 961 页说，第一版以来，开源视觉软件爆发式增长；Papers with Code 汇总最新论文和实现。书上第 962 页说，OpenCV 有 2500 多个优化算法，支持 C++/Python/Java/MATLAB；作者多年用 C++，近年转向 Python。经典算法先看 OpenCV；新论文先看 Papers with Code；写原型用 Python，部署再换 C++/GPU。工具没有绝对的最好，适合这个任务、这个团队、这个算力才重要；OpenCV 的 Python 接口底层是 C++，所以快，别在 Python 里逐像素循环；先会用，再读源码，不要一上来啃 OpenCV 实现；Features2D、calib3d、stitching 分别对应第 7/11/8 章。

看图 2。左边是输入，右边是同一行的亮度剖面；OpenCV、SciPy、NumPy 三条线完全重合，PSNR 约 120 分贝。这个数字说明三种结果几乎逐像素相同，不是画质更好；MSE 已经小到 1e-12 的量级。所以三种实现的差别不在结果，在速度和内存。选库时先确认数值一致，再比速度；如果结果都不一样，快也没用。如果 PSNR 很低，先查边界和数据类型，不要先怪库。

书上第 962 页说，NumPy 的多维数组能让人习惯矩阵思维，避免又慢又难写的像素循环。书上第 964 页说，PyTorch 和 TensorFlow 是当前最主流的深度学习框架，相比 NumPy 能用 GPU 做更快的数值计算。可以先学 NumPy 的广播、索引和矩阵乘法，再学框架的自动求导和 GPU；顺序反过来也能用，但容易把框架只当加速库。GPU 不是万能的，小图、小模型时数据传输开销可能比计算还大。PyTorch 研究生态更活跃，TensorFlow 部署工具更成熟，团队会哪个就用哪个。

看图 3。这张图列出八条路线：识别、检测/分割、特征匹配、光流、立体/深度、SfM/SLAM、三维重建、IBR/神经渲染；每条都给出数据集和工具。识别走 ImageNet/COCO + PyTorch；检测分割走 COCO + Detectron2；特征走 HPatches + OpenCV；SfM 走 1DSfM/ETH3D + COLMAP；三维走 ScanNet/DiLiGenT + Open3D。它没有穷尽所有资源，只是一张从任务出发的索引；先选任务，再顺着箭头找数据和工具；图里的工具只是入口，具体版本和许可证要自己查；找不到任务，就去 Papers with Code 按任务浏览；它不是课程表，同一任务可以有多种工具。

书上第 964 页说，Colab 提供免费 GPU 和 Jupyter，适合课程作业；Kaggle 提供在流行数据集上比拼模型的平台。没有显卡，先用 Colab 跑通；想练手，去 Kaggle 参加一场比赛；想复现论文，先看 Papers with Code 有没有代码。选工具先看三件事：任务、数据、算力；再看生态和社区；最后才看别人说哪个好。Colab 免费额度有限，长训练要接本地或云 GPU；免费资源适合学习，不适合长期训练；Colab 会断线、Kaggle 有提交限制，长期项目要准备预算。

书上第 970 页说，这本书没有官方幻灯片，但内容和作者在华盛顿大学合教的课程大致平行；Snavely 在 Cornell 的视觉导论课也是相关课程。学完这门课，下一步可以三条线走：想补基础，跟一门大学课；想追前沿，看会议和 Papers with Code；想做项目，选一个数据集从头跑到尾。三条线可以交替，但别只收藏不练；课程作业、开源项目、论文复现，三种练法都比被动看视频有用。别囤课，选一门跟完。建议先复现一篇论文的基线，再改一个模块，不要一上来造新算法。

这门课从像素开始，经过成像、处理、拟合、学习、识别、特征、对齐、运动、计算摄影、SfM、深度、重建、渲染，最后回到怎么找资源。算法会过时，工具会换，但从问题到数据到模型再到评估的思路不会过时；你带走的应该是这套思路，而不是某一个公式。课程到这里结束，你的项目可以开始了；选一个你真关心的问题，从一张图、一个数据集、一个基线做起。最后一集不布置作业，只留一个问题：你想用视觉解决什么？六层结构再走一遍：基础、建模、识别、运动、三维、渲染——你现在的项目落在哪一层？
