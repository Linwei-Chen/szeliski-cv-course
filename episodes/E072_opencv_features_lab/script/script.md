# E072 口播稿 · 实验课：OpenCV 特征全流程

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

书上第 417 页说，第 7 章讲的是特征检测与匹配。前面几集，我们把检测子、描述子、匹配和直线拆开讲过。这一集把它们串成一条能跑的 OpenCV 流水线：读图、提点、配对、筛匹配、估单应、叠图。每一环都能单独换。检测子可以换 SIFT，匹配可以换 FLANN，几何校验可以换仿射。先把默认版跑通，再谈替换。整条链只有几十行代码，难的是每一步的门槛怎么定。跑通了，你才知道每个数字是从哪来的。默认版跑通了，再换检测子或匹配器，才有可比的对象。

运行环境是 Python 三点一一，OpenCV 四点一三，NumPy 二点三。SIFT 和 ORB 都能用，随机种子也能固定。环境这一步最枯燥，但必须先过。版本不对，后面所有数字都对不上。本集不用装新东西，命令和版本都写在课程材料里。跑之前先确认 cv2 能导入，别等报错才找环境。把版本记进实验记录，换机器时先对版本，再谈结果。后面的数字都在这个环境里测出来。实验记录里写清楚版本，别人才能复现。

两张图都是九百六乘六百四，程序生成，单应已知。读进来先转灰度，因为 ORB 和 SIFT 都在灰度图上找特征。灰度不是丢信息，是先把亮度当唯一输入，免得颜色变化干扰。真实项目里如果颜色很重要，可以另做颜色描述子。读图时注意 dtype 是八位无符号。后面算距离、估单应，都在这个像素坐标系里，别中途换尺度。灰度图只有一层通道，画图时再转回彩色，不影响匹配。先把数据准备好，再谈算法。读图和匹配都在同一坐标系里完成，后面不用再缩放。

书上第 438 页说，ORB 给 FAST 检测子加上方向，再算带方向的 BRIEF 描述子。本集把特征上限设成一千，ORB 在两张图上各提一千个点。每个 ORB 描述子三十二字节，也就是二百五十六位。一千个点不是越多越好，上限是精度和速度之间的一个旋钮。ORB 的点带尺度和方向。上限一千是硬截断，场景纹理多就会顶满，纹理少就达不到。FAST 只负责找角点，方向来自灰度质心，尺度来自图像金字塔。上限设多少，要在你的任务上试。先看任务需要多少细节，再决定上限设多少。

看图。同样设一千上限，SIFT 在原图提一千个点，在变换图提一千零一个。多出来的那个点，是检测器在变换图边缘找到的，不是程序写错。书上第 436 页说，SIFT 描述子是四乘四格、每格八个方向，一共一百二十八维。图里圆的大小是尺度，半径方向是主方向。点不是随便撒的，尺度空间在决定谁留下来。一百二十八维浮点，存储和比较都比 ORB 的三十二字节重得多。两种距离不能混用，描述子长度也决定了存储和匹配成本。描述子的维度决定距离计算量，也决定内存占用。

书上第 441 到 443 页说，匹配的第一步是选策略，最简单的就是按描述子距离找最近邻。ORB 用 Hamming 距离，SIFT 用欧氏距离。两张图各有一千个描述子，KNN 给每个点留两个候选。为什么留两个？因为最近的那个不一定是真匹配，第二近的可以当参照物，下一刀就靠它。crossCheck 先关掉，因为后面要自己写互检。k 等于二，才有次近邻可以比较。Hamming 用异或数一，欧氏用平方和开方，匹配器必须和描述子配套。候选留多少个，取决于后面的筛子。k 取更大也可以，但后面的筛子要跟着改。

书上第 444 页说，最近邻距离除以次近邻距离，比值小于阈值才留下，这叫比率测试。阈值设零点七五。ORB 从一千条候选里剩四百三十一条，SIFT 剩四百五十二条。这个比值在问：第一名比第二名强多少。强得不够明显，就宁可不要。比率测试不需要知道哪个是正确匹配，它是一个无监督的筛子。阈值是超参数，不是定理。阈值调低更严，调高更松。直观说，最近和次近差不多就扔掉，差得远才留下。比值测试不依赖真值，所以新场景里也能先用。

书上第 445 页说，互检要求 A 到 B 的最近邻和 B 到 A 的最近邻互相指认。互检后 ORB 剩三百三十条，SIFT 剩四百零七条。比率测试管像不像，互检管是不是彼此的唯一。两条都过，才算一张双向票。它会误杀一些真匹配，但假匹配掉得更多。互检要再跑一遍反向 KNN，计算量翻倍，不过后面 RANSAC 会轻松很多。互检可以手工写，也可以用 crossCheck，两种语义略有差别，别混着讲。双向都认，才算稳定。互检是双向投票，单向最近邻不算数。

看图。书上第 447 到 448 页说，几何校验用 RANSAC，反复抽样拟合，再数有多少点符合模型。单应阈值三像素。ORB 从三百三十条里留下三百一十七个内点，SIFT 从四百零七条里留下三百九十。图里绿线是最后的内点，红线是被淘汰的匹配。到这一步，匹配已经不是看起来像，而是几何上说得通。单应至少需要四个点。RANSAC 每次抽四对，拟合一个变换，再数有多少对落在三像素内，重复很多次，取内点最多的模型。阈值太大，会把外点当内点；太小，会把内点踢掉。RANSAC 带随机性，同一组数据多跑几次，内点数可能略有出入。

把内点代回单应，ORB 的中位重投影误差是零点七七像素，SIFT 是零点二八像素。ORB 的内点率约百分之七十三点五，SIFT 约百分之八十六点三。这两个数不是给算法排座次，是告诉你这套参数在这组图上有多稳。换一张图，数字会变，判断方法不变。重投影误差，就是把原图内点按单应投到第二张图，再和它实际匹配点量距离。中位数比平均值更抗离群。内点率高不代表匹配多，要同时看绝对数和比例。误差单位是像素，不是抽象分数。用中位数，是因为少数错匹配会把平均值拉高。

看图。用单应把第二张图搬回第一张图的坐标系，五五叠加，得到左边这张。右表把两套数放在一起：特征点、比率后、互检后、内点、内点率、中位误差。这就是拼接的前哨。单应估对了，图就能对齐。完整拼接还要处理曝光、接缝和融合，那是下一章的事。注意搬的是第二张图，所以用单应的逆。叠加只是检查对齐，不是最终融合，接缝处会看到亮度差。重影越小，单应越准；重影大，先回去查匹配。对齐是拼接的必要条件，不是充分条件。对齐检查只看重影，不看颜色，颜色差是曝光问题。

本机单次运行，ORB 的检测耗时更短，两者匹配耗时都在毫秒级。SIFT 在这组图上内点更多、误差更小；ORB 描述子更短、检测更快。别急着宣布谁赢。这组图是程序生成的平面场景，纹理足、重叠大。SIFT 的优势来自浮点描述子的精度，ORB 的优势来自二进制比较的速度。换一张低纹理、视角变化大的图，排序可能反过来。单次耗时受缓存和 CPU 调度影响，不能当基准。要看速度，至少跑十次取中位数，还要固定图像大小和特征上限。报告速度要写机器、图像大小和特征上限，别人才能复现。

这套流水线最怕三件事。第一，纹理重复。一排一样的窗户，比率测试会把错窗户当最近邻。第二，重叠太小或遮挡太多。内点不够，单应直接估飞。第三，场景不是平面。单应只能对齐一个平面，前后景会错位。本集故意加了右下遮挡和亮度变化，就是为了让你看到内点数会掉。重复纹理不只会错配，还会让 RANSAC 抽到一致的错误模型。低纹理场景要先加纹理，或者换检测子。如果场景有大面积天空或白墙，检测子找不到点，这不是代码错。知道怎么翻车，才知道怎么兜底。遮挡和亮度变化，都是真实拍摄里常见的情况。

书上第 441 到 448 页说，匹配策略、比率测试、互检、RANSAC 是四道独立的筛子。本集的参数是特征上限一千、比率零点七五、RANSAC 三像素。复现时先固定这三项，再改一项看数字怎么动。一次改三个，你根本不知道是谁的功劳。画图时内点和外点要分色，不然你只会看到一团线。建议把每步数量打印出来：特征数、比率后、互检后、内点数。数字突然掉一半，往往就是参数或数据出了问题。参数要写进实验日志，不然一周后你只记得大概调过。把参数写全，比只记一个最终内点数有用。

把这一集往回看：角点那一集、尺度空间那一集、一百二十八维描述子那一集、匹配那一集、直线那一集、学习型描述子那一集。这一集没有新算法，只是把旧名字按顺序接起来。能把这六集串成一条流水线，比记住六个缩写更有用。真实项目里，算法不是一个一个出现，而是一条链。如果哪一步听不懂，回到对应那一集看原理。这一集的任务，是让你看到它们在代码里怎么排队。这一集是第 7 章的收束，也是第 8 章的起跑线。把链条讲清楚，比堆名词更重要。每一集讲原理，这一集看它们怎么在代码里排队。
