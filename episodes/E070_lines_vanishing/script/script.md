# E070 口播稿 · 直线也有脾气：LSD 直线检测与边缘连接

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

书上第 477 页说，边缘和一般曲线适合描述自然物体的轮廓，但人造世界满是直线。检测和匹配这些直线，能用于建筑建模、城市环境里的位姿估计，还有印刷文档的版面分析。门框、桌沿、斑马线、文档表格，都是生活里的例子。在人造环境里找直线，常常比找角点更划算。这些线条出现得规整，位置也稳定，检测起来比自然轮廓省力。

这一节的路线分三步。书上第 477 页说，先把曲线近似成分段折线。再讲 Hough 变换，它能把边缘点分组成线段，中间有缺口或者被遮挡也能接上。最后讲怎样把共享消失点的三维直线分组；消失点可以用来标定相机、确定朝向。三条路线不互斥，实际系统经常混着用。实际系统里，三步常常前后呼应：折线给局部方向，投票把断线接起来，消失点再提供全局约束。

折线简化也叫直线简化。书上第 477 页说，最老最简单的做法由 Ramer 和 Douglas-Peucker 提出：递归地在离两端点连线最远的点处细分曲线。如果最远点还不够远，就停下来。Hershberger 和 Snoeyink 后来给了更高效的实现。本集实验里，递归 4 层，留下 9 个顶点。容差选大一点，顶点少、线更直；选小一点，贴曲线但碎。判断要不要继续分，就看这个最远点离端点连线有多远；远就留下，近就丢掉。容差这个旋钮，直接决定折线是粗还是细。

折线算出来以后，可以近似原曲线。书上第 477 页说，如果想要更光滑的表示或者可视化，可以用逼近样条或插值样条。要匹配、要计算，用折线更省事；要展示、要好看，再套一层样条。折线保留拐点，样条负责过渡；两者可以叠在一起用。

折线近似常常够用，但真实世界的线有时断成几段，或者由很多共线小段组成。书上第 478 页说，很多时候希望把这些共线小段合并成更长的直线。Hough 变换就是让边缘点给可能的直线位置投票的经典技术。它的强项是把断掉的证据攒起来，跨过缺口接成一条线。缺口和遮挡正好是折线的短板，投票能把分散的证据重新聚起来。

书上第 478 页讲原始 Hough：每个边缘点给所有经过它的直线投票，累计值高的格子再拿去做直线拟合。图 7.46 画得很清楚：一个点在 (r,θ) 空间里扫出一条正弦曲线。同一条直线上的点，正弦曲线会交于同一点，交点就给出直线方程。参数空间里的一个峰，背后是一整条线上的点。投票时不用预先知道线在哪，所有点一起把候选位置抬出来。

如果线上的点不够稀疏，书上第 478 页给了更好的办法：用每个边缘点的局部方向，只投一个累计格。图 7.47 画了定向 Hough，边缘点先做极坐标重参数化，再在 (r,θ) 累计数组里投票。第 479 页又说，有时也可以围绕估计方向投少数几个相邻格，作为折中。既然知道边缘朝哪，就不必把所有方向都投一遍，速度和抗噪都会好一些。局部方向通常来自边缘检测：梯度方向给法向，切线方向给直线走向。

投票之前要先选直线的表示。书上第 479 页说，图 7.48 用法向-距离参数化，也就是法向 n 和原点到直线的距离 d。约定法向和图像梯度同向，再把法向转成角度 θ。每个轴用多少格，取决于边缘点位置和方向的精度，还有预期的线的密度，最好拿样例图实验定。格子太粗会糊，太细会散。表示选错，后面的投票和拟合都会跟着错。

要让 Hough 好用，还有不少细节。书上第 479 页说，投票时可以用边缘段的长度或者强度。累计数组里可以保留组成该格的边缘点列表，方便后处理。也可以选择把不同极性的边缘合并到同一条线段里。这些细节不改变原理，但决定实现出来能不能用。后处理时拿到成员边缘点，就能重新拟合、合并或者剔除短段。

二维极坐标之外，还可以把完整的三维 (n,d) 线方程投到单位球上。书上第 479 到 480 页说，球坐标采样不均匀，还要三角函数。另一种做法是投到单位立方体的面上，也就是立方图。取绝对值最大的分量选一个面，另外两个坐标除以它当索引；这样避开三角函数，但要多一些判断。如果忽略边缘极性、限制 d 非负，还能用半立方，只留三个面。六面立方图比球面好实现，代价是每个点要多做几次比较。

Hough 之外的另一条路是 RANSAC。书上第 480 页说，它随机取两个边缘点，形成一条直线假设，再数有多少其他边缘点落在这条线上。如果边缘方向足够准，甚至一个边缘点就能产生一个假设。内点数足够多的直线，就被选为要找的线段。先随便猜一条线，再看多少人站队，站队多的假设留下。假设不需要覆盖所有线，只要有一条命中，内点就会把它抬出来。

RANSAC 的优点是不需要累计数组，所以更省空间，也不那么受分箱大小影响。书上第 480 页说，缺点是要生成和测试的假设可能比 Hough 找峰值多得多。一个省内存但费猜测，一个费内存但一次投票就能聚出峰；看场景更怕哪一头。场景里线多、噪声大时，这个差别会很明显。

第三条路是自底向上分组。书上第 480 到 481 页说，把方向相近的边缘点迭代地聚成定向矩形，叫线支持区。这些区域是否成立，用统计分析判断；LSD 论文就是这么做的。LSD 很快，能把线段和纹理区分开，而且开源，所以在实践中很常用。它不要求先知道有几条线，线段会自己长出来。线支持区的大小和方向由局部证据决定，不需要全局的参数网格。

近几年也有深度神经网络，同时提取线段和它们的交点。书上第 481 页提到这一点。传统方法给你线段，网络还能顺手告诉你哪两条线在哪个拐角相交，后面的线框重建更省事。线段和交点一起出来，后面的平面、线框和结构推理都方便。

总的来看，哪种直线估计技术最好，书上第 481 页说并没有明确共识。所以最好先想清楚问题，再实现几种方法，比如折线简化、Hough、RANSAC，看哪个最适合你的应用。数据一变，赢家可能就换人。先做基线，再比较，别一上来就追最新模型。同一张图，换个阈值或者换个场景，排名可能就变。

很多场景里，结构上重要的直线共享同一个消失点，因为它们在三维里平行。书上第 481 页举了建筑的水平边和垂直边、斑马线、铁轨、家具边。找到这些消失点，可以帮助精化直线位置，有时还能定相机内外参。第 482 页的图 7.51 是矩形检测的例子：室内走廊、建筑立面、语法识别、平面扫描匹配；也可以用网络提线段和交点，再建三维线框。直线先讲到这里。下一集转向分割，讲图割、均值漂移和归一化割。消失点把散落的线段组织成一组平行方向，后面的重建就有了抓手。
