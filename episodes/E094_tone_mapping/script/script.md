# E094 口播稿 · 明明白白压回来：色调映射 Tone Mapping

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

书上第 627 页说，辐亮度图算出来以后，通常要显示在低动态范围的 8 位屏幕或打印机上；色调映射就是把大范围压回可显示范围。这不是简单调亮或拉对比，而是决定哪些亮部保留、哪些暗部让路。同一张 HDR 可以映射出很多种风格。压得太狠会发灰，压得太浅高光又白掉。人眼能同时看室内外，是因为局部适应；屏幕只有一个全局范围，所以必须做取舍。映射完的输出仍然是显示值，不是原始辐亮度。

书上第 627 页先讲 HDR 怎么存。不差空间就用 32 位浮点 RGB；PPM 可以扩成 PFM，TIFF 也支持浮点；更紧凑的是 Radiance 的 .hdr，用公共指数加每通道尾数；OpenEXR 用 16 位浮点，GPU 原生支持；更新的还有 JPEG XR。格式决定能不能存超过 1 的亮度；8 位 PNG 和 JPEG 存的是显示值，不是辐亮度。做算法实验时，尽量保留浮点中间结果；一旦存成 8 位再想压，亮部信息已经没了。选格式时先看后续处理，别中途降到 8 位。

书上第 627 页说，色调映射方法分两类：计算空间变化的传递函数，或者压缩图像梯度去适配动态范围。前者按位置决定这里压多少，后者先看变化量、再重建；全局曲线是最简单的特例。选择哪一类，取决于你要保细节还是保全局对比。全局算子快、稳、不会出局部光晕；局部算子能救回大范围细节，但参数更敏感，也更容易出伪影。实际使用时，两类方法也可以组合，先用全局定基调，再用局部补细节。

书上第 627 页说，最简单的是全局传递曲线，比如用 gamma 把 HDR 映回显示域。如果对每个通道分别做 gamma，颜色会变淡，因为高值通道按比例贡献变少；先取亮度通道做映射，再按比例带回颜色更好。逐通道 gamma 会把颜色比例改掉，亮度路线保住色相。看图：按第 60 百分位曝光做线性裁切，窗户外全白；逐通道 gamma 发灰，亮度路线天空和草地还有颜色。全局曲线的缺点是只有一个压缩策略，遇到特别亮的窗户和特别暗的角落，总有一头保不住。先定曝光基准，再选曲线，结果会稳定很多。

书上第 628 页把图像拆成亮度与色度，再对 log 亮度 H 做低通得到 base，相减得到 detail；base 管大范围明暗，detail 管边缘和纹理。在 log 域里，压暗变成减一个数，细节不会被一起压没，这就是局部色调映射的基本做法。分开以后，可以只压 base、不动 detail，也可以按需调整两层的比例；色度单独保留，最后再乘回去。压 base 的强度就是一个参数，调它等于调全局对比。

书上第 627 到 628 页说，全局曲线在曝光范围很宽时仍保不住细节，需要像暗房里的 dodging/burning 那样按局部平均亮度调整；数学上近似于除以邻域平均亮度。亮的地方多压、暗的地方少压，本质是局部曝光。邻域越大越平滑，越小越容易出光晕；这就是后面为什么要用保边滤波。dodging/burning 不是作弊，它是在有限显示范围里重新分配注意力。邻域尺度和图像内容有关，没有一套固定参数适合所有图。

书上第 628 页说，base 被压到目标 log 范围，再和 detail 相加，指数回去就得到压缩后的亮度。这里要提醒，式 10.14 印成 H_H 等于 s 乘 H_H，但同页正文说压的是 base，Figure 10.19 的图注也写 attenuating the low-pass log luminance image；按上下文应以 base 为准，读书时别被下标带跑。压 base、留 detail，才既降对比又保细节；如果真按字面去压 detail，等于把边缘和纹理一起削掉，图会糊。读书时把公式和正文、图注放在一起看，能避免这类下标歧义。

书上第 629 页说，线性低通不是保边滤波，detail 在高对比边缘会出现可见晕轮，最后的图里也能看到。高斯把亮暗边界抹开，base 在边缘变缓，detail 就多出亮边和暗边；压完再重组，边缘像描了一圈。看图：detail 的蓝红边就是晕轮，双边 base 没有。晕轮在天空、窗户、树梢这些高对比处最明显，也是局部色调映射最常被提到的伪影。晕轮不是噪声，是滤波跨过边缘造成的结构性误差。

书上第 630 页说，解决办法是用保边滤波器做 base；Durand 和 Dorsey 比较了各向异性扩散等方法，最后选双边滤波。双边在空间近、亮度也近的像素之间平均，跨过强边缘就不混；所以 base 保住边缘，detail 不再有晕轮。代价是双边不是线性滤波，参数更敏感、计算更贵；后来还有 WLS 等替代。σ_s 管看多远，σ_r 管差多少还算同一类，两个都要按图像内容调。双边也要调窗口，窗口越大越慢。

书上第 630 到 631 页给出另一条路：不压 base，压它的导数。先求 log 亮度的梯度，用空间变化的衰减函数压大梯度，再解泊松方程把梯度积分回图像。大梯度是强边缘和大范围明暗变化，压它就能压全局对比；小梯度是纹理，尽量保留。重建是解最小二乘，和泊松融合是同一个方程；解出来只差一个常数，所以亮度基准要另外定。看图：Φ 在边缘小、在纹理处大，重建后大范围明暗被压平，纹理还在。梯度域直接改导数，所以对强边缘的压制更直接。

书上第 633 到 634 页说，还可以让用户画几笔曝光调整，再用局部加权最小二乘把稀疏笔触插值成平滑的曝光修正图；平滑权重和 log 亮度梯度成反比，所以平坦区更平滑、边缘处更敢跳。这就是局部 dodge/burn 的半自动版；λ、α、ε 控制平滑和保边。书上第 634 页脚注给了一组默认值。全自动时，把每个像素的目标曝光设好，也能用同一套 WLS 生成调整图。WLS 是二次型，解一个稀疏线性系统就行，比双边更容易做全局优化。笔触越稀疏，插值越依赖平滑项，结果也越平滑。

看实验读数。合成 HDR 场景动态范围约一万五千六百倍；按第 60 百分位曝光做线性裁切，66.3% 的像素丢高光；逐通道 gamma 平均饱和 0.15，亮度路线 0.28；高斯 base 晕轮 69.6%，双边 7.4%；双边保住阶跃 100%；梯度域压掉 99.6% 的梯度能量，这只说明大梯度被压，不等于画质提升；泊松重建误差 0.00%；WLS 在平坦区把噪声标准差压掉约一半，同时保住阶跃。这些是合成实验，没有真实相机的噪声和对齐误差；数字说明趋势，不是画质排名。真实照片还要考虑噪声放大、色域映射、局部对比过强导致的塑料感。这些读数都来自同一套合成图和同一组参数，适合横向比较。

选算子先看动态范围：差两三档，全局曲线就够；差很多档，再上局部。局部映射先保边，再谈压多少；base 压太狠会发灰，detail 放太大会有光晕。颜色走亮度通道，别逐通道硬压；输出前检查高光是否全白、暗部是否死黑。最后，色调映射没有唯一正确答案，只有这张图想让人看什么。工程上先定目标风格，再调参数，比反过来更容易复现。

这一集收成三件事。第一，色调映射是把辐亮度压进显示域。第二，全局曲线简单，但保不住大范围细节；局部 base/detail 和梯度域能保细节，但怕晕轮。第三，保边滤波，双边或 WLS，是局部算子的关键。下一集换到超分辨率，从多帧对齐到学习式放大。下一集见。
