# E057 口播稿 · 图像分类简史：手工特征全景与深度网络前夜

> 本稿为课程口播整理，配合 [幻灯片](../slides/deck.html) 学习。

上一集我们把认出一个的检索提速讲完了：视觉词袋加词汇树，几十亿张图也能查得飞快。这一集回到第 6 章主线，换个问法，认出这一类。书上第 349 页，图像分类正式开篇：不再问图里有没有某个具体物体，而是问，这张图拍的是哪一类。上一集是点名单个，图里有没有这只杯子；这一集是发底牌归类，这是杯子，这是键盘，还是别的。任务一换，打法也跟着换。篇幅原因，本集只讲最经典的三个板块。

分类这活儿有多难？书上第 349 页摆出一组照片：十类物体，让你写个程序把它们各归各类，而且必须给以上都不是留一个选项，分不出来就老实承认。书上同一页还补了一句宽心话：十年之间，这个领域的进步相当惊人，今天算法的水准比十年前强太多了。以上都不是这个选项是诚实底线，现实世界不会只给你十类照片；十年剧变这句话，也预示着后面每一步都在给一场巨变铺路。

第一招，词袋。书上第 352 页说，这是分类识别里最简单的算法之一，名字就叫词袋，也叫特征袋、关键点袋，三个名字一回事。做法写得很直白：数一数查询图里各类视觉词出现的分布，做成一张直方图，拿去跟训练图像的直方图比对，谁跟它最像，它就是哪一类。这有点像靠文风认作者：不细读句子，只数的、了、是各出现多少次，文章是谁的手笔，八九不离十。词袋把整张图压成一页账本，分类就变成了对账。

跟上一集的实例识别比，词袋最大的不同在哪？书上第 352 页挑明：少了几何验证这道关。上一集靠验证筛掉假配对，这里干脆不做。原因书上也给了：同一类物体，不同照片里特征的空间一致性本来就弱。流水线画成四步：提特征、聚类成视觉词、统计直方图、分类器判决。实例识别认的是这一张，部件位置错一点都不行；分类认的是这一类，摆什么姿势都算，验证自然就省了。省掉验证是任务性质决定的，跟偷懒无关。

谁先把词袋用起来？书上第 352 到 353 页说，Csurka 等人在二零零四年首创关键点袋这个词。他们用仿射协方差区域配 SIFT 描述子提特征，K 均值聚类建视觉词表，再拿朴素贝叶斯和支持向量机两种分类器同台对决，支持向量机胜出。到二零零六年，他们的升级版改用普通 SIFT 块加 boosting，还掺进少量几何一致性信息。Csurka 团队这场二零零四年的分类器对比，支持向量机赢了，后来者大多沿这条路线继续改进。

词袋这台机器，零件可以怎么换？书上第 353 页说，Zhang 等人做了细致的对比研究：特征检测器换着试，比如 Harris–Laplace 和拉普拉斯；描述子换着试，SIFT、RIFT、SPIN 都上场；支持向量机的核函数也换着试。三个维度各比一轮，哪种组合更好用，让数据说话。这像装修房子：水电、家具、软装分开选配，单看哪件都好看，凑一起未必协调，所以得整套试。

直方图有个先天短板：只数总数，词与词之间毫无关系。书上第 353 页说，Grauman 和 Darrell 干脆不做量化，直接对两组规模不等的特征集合近似算距离。做法是把特征向量按多分辨率金字塔逐层装箱，数哪些特征落进对应格子，再用直方图交集逐层比对，越细的层权重越高。后续工作还给出免显式建塔的哈希加速。好比比较两个书架：先看大类分布，再看小类摆放；越细的层越能区分品味，但先粗后细才不吃亏。

受此启发，书上第 353 页说，Lazebnik、Schmid 和 Ponce 把类似思路搬回图像平面，给词袋加上二维空间位置的粗粒度概念，做出空间金字塔：把图按层级切格子，每层统计格子里的词频直方图，再用金字塔匹配核逐层融合。特征提取也按前人结果改成密集网格采样，描述天空这类无纹理区域时更给力。词袋是只数不看位置，空间金字塔是分区点名。打个比方，楼上楼下各有多少，账本一翻就清楚。本页示意图是程序生成，未用教材或论文原图。

量化到底好不好？书上第 353 页说，这场争论打了多年：用量化描述子还是连续描述子，用稀疏还是密集，众说纷纭。Boiman、Shechtman 和 Irani 给出漂亮一击：把查询图的特征跟类别全部特征直接比最近邻，不是一张张图各自为战，再配上朴素贝叶斯分类器，效果胜过量化视觉词。量化像把千人千面印成标准像，快是快，细节全糊；直接见真人，慢工出细活。这一局，不量化的赢了。

特征本身也可以学出来。书上第 353 到 354 页说，不用通用检测器和描述子，有作者专研类特异特征，常用随机森林实现；还有人把特征生成和图像分类两段合并训练；另一路借鉴生物视觉皮层的层级密集特征变换，配上支持向量机做最终分类。这些特征也学一下的尝试，为深度网络做了铺垫。手工特征的时代还剩最后几页，下一集就进入深度网络。

第二板块，部件模型。它比词袋老得多。书上第 354 页说，找到部件、量好它们的几何关系，是物体识别最老的路线之一，一九七三年就有了；人脸识别、行人检测、姿态估计里一直用到今天。同一页还交代了名字的来历：Fischler 和 Elschlager 把这套思路起名叫图画结构，部件之间像弹簧一样连着，可拉伸可压缩。词袋把人拆成一堆散件，部件模型是装上关节的木偶：散件不问摆法，木偶讲究连接。这一字之差，就是后面所有复杂度的来源。

怎么把弹簧变成可计算的？书上第 354 到 355 页给了个能量函数：两部分相加，每个部件自己的匹配得分，加上成对部件间的关系得分；拟合就是找一组部件位置，让总能量最小。遍历所有位置当然太贵。书上第 355 页说，Felzenszwalb 和 Huttenlocher 把部件关系限制成树形，动态规划先优化叶子再往回收，学习与推断都更可行；再把成对能量限定成马氏距离，第 5 章提过的老朋友，配上快速距离变换，每个相互作用的耗时接近线性。树形结构的意思是，每个零件只听一个上级的话，不用开全员大会，一层层定案就行。

部件间的连线方式，书上第 355 到 356 页列了一整张谱系，从简到繁。最简是词袋，部件之间毫无几何关系，效率高但完全画不出空间排布；树和星形推断最高效；有向无环图排在其后，代价是被迫加上因果结构；k 扇形配距离变换能把复杂度往下压；全连接的星座模型最通用，可部件一多，指派问题就变成不可解。谱系就是管多少、付多少的天平：连线越密越能精描细画，算力账单也越滚越大。本页示意图是程序生成，未用教材或论文原图。

第三板块，上下文。书上第 356 到 357 页说，此前我们多半把认出物体和读懂场景分开对待，只认物体不问场景，是大短板，上下文在人类识物里举足轻重。证据很妙：书上第 357 页摆出两张照片，让你把圈出的物体全认出来；再把它们转个九十度，原来全都是同一个墨渍形状！光靠形状认物体，人自己都会翻车。同一坨形状，放在厨房里像厨具，放在车库里像工具；场景给的信息，物体自己给不了。

上下文怎么进模型？书上第 357 页盘了家底：其实前面的工作已经在用上下文。空间金字塔就是把空间统计算在不同区域上，部件模型用的是局部上下文。部件模型与上下文模型的最大差别，在于后者把物体组装成场景，而且每类物体有几个事先不知道。Sudderth 等人的两层星座模型给了完整样例：顶层用高斯建模物体间的相对分布，底层用高斯混合建模部件分布，物体与部件的数量未知，交给隐狄利克雷过程建模。一层管什么跟什么挨着，一层管每个物体长什么样；场景当整体来读，不是一张物体清单。

收个尾。这一集把认出这一类的手工特征全景走了一遍：词袋只数不看位置，金字塔把空间加回来，部件模型装上弹簧关节，上下文把场景当整体读；它们各有所长，也各有代价。这些方法像一条渐强的前奏，特征在学，结构在深，上下文在合，就差一阵东风。书上第 358 页把这层意思点透了：整图匹配这些做法的种种好处，正是深度神经网络的中心收益。下一集，深度网络见。
